# Pano 图形界面设计

> 本文档随 M1.2 更新：UI 迁移 Tauri v2，组件与窗口分离（窗口由主程序管理，组件经 API 控制窗口）。
> 设计背景：egui/eframe 单事件循环多窗口挤占为架构性限制（实测见 `roadmap.md` §M1.1），Tauri 多 WebView 独立渲染根治。
> M2.2 更新：**每个窗口分配 / 切换一个 UI 组件**，UI 组件声明所需 series（取代「窗口直接指定 series」）。

## 1. 设计目标

- **信息密度高、实时性强**：监控面板一屏看全；
- **多窗口 + 托盘常驻**：各 UI 独立窗口，可单独置顶 / 全屏 / 绑定显示器；应用驻留系统托盘；
- **组件与窗口分离**：组件只描述内容（画什么）+ 窗口需求（`WindowSpec`），窗口由主程序管理的窗口服务（pano-window）统一创建与控制；
- **适配器管理直观**：启停、配置、状态一目了然；修改即时生效；
- **主题可切换**（默认暗色）；
- **UI 与数据解耦**：只按能力 / series 取数，UI 整体可替换。

## 2. 窗口模型（组件与窗口分离）

```
┌─ 系统托盘（Pano 常驻入口）────────────────────────┐
│  ├ 打开管理窗口（适配器+窗口+设置）               │
│  ├ 窗口列表（动态：全部窗口，随运行时注册表重建）  │
│  └ 退出                                         │
└────────────────────────────────────────────────┘
┌─ pano-app 主程序 ───────────────────────────────┐
│  WindowService（pano-window）：按 WindowSpec 建窗 │
│  · 管理窗口（1 个）                               │
│  · 监控窗口（0..N 个，运行时注册表）               │
└────────────────────────────────────────────────┘
┌─ pano-ui 组件（纯内容）─────────────────────────┐
│  · 渲染函数 + WindowSpec 声明                    │
│  · 持 WindowHandle，经 API 控制自己的窗口         │
└────────────────────────────────────────────────┘
```

| 窗口 | 内容 | 说明 |
| --- | --- | --- |
| **管理窗口**（1 个） | 适配器管理页 + 窗口管理页 + 全局设置页（页签切换） | 从托盘打开；可置顶 / 全屏 / 绑定显示器；**不可销毁**，无组件内容 |
| **监控窗口**（0..N 个） | 分配 / 切换一个 **UI 组件**；组件声明其所需 series（`UISpec.components` 组件目录） | 「窗口管理」页新建 / 分配组件 / 切换组件 / 隐藏 / 销毁；组件经 `WindowHandle` API 控制自己的窗口 |

关键语义（M1.1 延续 + M1.2 变更 + M2.1 窗口管理 + M2.2 UI 组件）：

1. **无传统主窗口**：应用驻留系统托盘；关闭任何窗口 = 隐藏（不退出进程），托盘「退出」才是真正结束；
2. **组件 = 内容 + 窗口声明**：组件声明 `WindowSpec`（标题 / 尺寸 / 置顶 / 全屏 / 显示器偏好），窗口服务据此建窗并把 `WindowHandle` 交给组件；**组件不持有任何窗口实现**（R1）；
3. **窗口控制走 API**：全屏、置顶、绑定显示器、位置 / 大小、聚焦、显示 / 隐藏、销毁，全部经 `WindowHandle` 调用（R2）；前端页面按钮 → Tauri 命令 → 窗口服务；
4. **显示器绑定**：API 或配置指定在哪个显示器打开；关闭时记录所在显示器 / 位置，重启恢复（布局持久化）；
5. **数据流不变**：所有窗口订阅同一个 `SampleStore` 的事件（§6），控制走同一个 `Lifecycle`；窗口数量不影响 core / adapters；
6. **重绘**：数据变化 → core 桥接层 emit → 各窗口前端 listen，各自渲染（无轮询、互不阻塞）；
7. **关闭顺序**（架构 §5）：托盘「退出」→ 停止全部适配器 → 结束进程；
8. **运行时窗口注册表**（M2.1）：`AppState.windows` 是「当前存在哪些窗口」的唯一来源。启动时由 pano-app 从 `UISpec.components` 播种（连同管理窗口），此后「窗口管理」命令层在此增删改；托盘「窗口列表」经 `refresh_tray` 回调据此动态重建（`TrayIcon::set_menu` 热更新）；
9. **UI 组件目录**（M2.2）：`UISpec.components` 声明**可分配的 UI 组件类型**（`ComponentSpec`：id / name / 固定 series / 默认窗口），是「窗口能展示什么」的来源。监控窗口**持有组件类型 id**，其展示的 series 由目录解析得出（**不再直接存 series**）；**多个窗口可绑定同一组件类型**（注册表以窗口 id 为键）；
10. **动态窗口 + 持久化**（M2.1 + M2.2）：可在「窗口管理」页新建监控窗口（选组件类型）或对已开窗口**切换组件**（仅换内容 / series，标题与几何不动）；切换组件时命令层向该窗口 emit `pano://window-component` 事件，前端据此重载内容。运行时**监控窗口集合**写入 `[ui].windows`（**段缺失** = 首次运行按目录播种并写回；**段存在但列表为空** = 用户已销毁全部监控窗口，保持为空），`[window.<id>]` 段持久化组件绑定 + 标题 + 布局，重启恢复。

## 3. 管理窗口（适配器 + 窗口 + 设置）

合并为一个独立窗口，内部页签切换（适配器 → 窗口 → 设置，M2.1 加入「窗口」）。

### 3.1 适配器管理（初期重点）

表格形式，每行一个适配器：

| 列 | 内容 | 交互 |
| --- | --- | --- |
| 状态 | 徽标（绿=运行 / 灰=停止 / 黄=启动中 / 红=错误） | 悬停 tooltip 显示错误详情 |
| 适配器 | 名称 + id + 描述 | — |
| 能力 | capability 标签（含 `RemoteSource` 标记） | — |
| 采样间隔 | 可编辑数字 + 单位 | **修改即生效**（拖动停止时应用） |
| 启用 | 开关 | **切换即生效**（即时启停） |
| 操作 | 重启按钮（Error 状态可用） | 手动恢复 |

- **配置表单由 `config_schema` 驱动渲染**（数值 / 文本 / 枚举 / 开关），避免 UI 硬编码适配器参数；
- 修改配置 → **即时生效**：写回 `pano.toml` → 仅重启该适配器；启停 / 采样修改在**后台线程 / 异步命令**中执行（stop 的阻塞不卡 UI），成功 / 失败 toast 提示（M1.1 实测教训，见 roadmap）；
- 防抖：采样间隔拖动过程不触发重启，`drag_stopped` / 失焦才应用；
- **M4.1**：适配器列表上方提供「连接远程适配器」入口（输入 endpoint + 可选 token）→ `connect_remote` → 成功后在列表出现该远程适配器（状态 / 启停 / 热重载同本地适配器）；连接失败 toast 提示（architecture §14.1）。

### 3.2 窗口管理（M2.1 + M2.2）

位于适配器之后、全局设置之前，管理监控窗口的生命周期与组件分配：

| 能力 | 说明 |
| --- | --- |
| 新建窗口 | 输入窗口 id（全小写 ASCII 连字符）+ 标题（可选，默认 = 组件默认标题），从**组件目录**选择一个组件类型分配（`create_window(id, component, title?)`）；组件依赖的适配器未注册时不可选 |
| 分配 / 切换组件 | 把目标组件类型应用到窗口（`set_window_component(id, component)`，可换成另一组件；**仅换内容 / series，标题与几何不动**）；对已打开窗口经 `pano://window-component` 事件通知其重载 |
| 显示 / 隐藏 | 即时切换窗口可见状态（`window_show` / `window_hide`） |
| **无边框开关（M2.4）** | 每监控窗口可切换系统边框（`window_set_decorations(id, enabled)`）：**无边框** = 去掉系统标题栏，内容区（组件声明的 `data-pano-drag` 区域 + 窗口壳 header）**鼠标拖动直接移动窗口**；窗口级覆盖持久化到 `[window.<id>].decorations`，重启恢复；管理窗口不可用（其内容无拖拽标记） |
| 销毁窗口 | 彻底关闭并从窗口管理器移除（区别于隐藏）；管理窗口不可销毁 |

- 窗口列表含管理窗口（标记「管理」，不可销毁）与全部监控窗口，显示当前可见状态、分配的组件与**边框状态**（「有边框 / 无边框」开关）；
- 改动后同步触发托盘「窗口列表」重建（`refresh_tray`）并写回 `[ui].windows` / `[window.<id>]` 持久化；动态创建的窗口即时进入托盘列表，重启恢复；
- 命令：`list_windows` / `list_components` / `window_content` / `create_window` / `set_window_component` / `destroy_window` / `window_show` / `window_hide` / `window_set_decorations`。

### 3.3 全局设置

- 主题（暗 / 亮）、默认采样间隔、环形缓冲容量；
- 查看当前 `pano.toml` 配置；
- 窗口布局（位置 / 显示器记忆）查看与重置；
- M1 为骨架，M3 完善。

## 4. 监控组件窗口（信息与曲线）

- 每个可分配单位为一种 **UI 组件类型**（`ComponentSpec`：id / name / 固定 series / 默认窗口），由 `UISpec.components` 组件目录声明；监控窗口持有一种组件类型，前端按组件 id 分派渲染器（M2.3 起可注册专用渲染组件）；
- M1.2 决策「1 组件 = 1 窗口」延续为「**1 窗口 = 1 组件**」：首次运行按目录播种默认监控窗口（label = 组件 id，仅当组件 series 存在数据源）并写回 `[ui].windows`；此后窗口集合由配置持久化恢复，可经窗口管理页新建 / 切换组件；多个窗口可绑定同一组件；
- 组件内容：组件名 + 最新值 + 最近窗口曲线 + 窗口控制按钮（置顶 / 全屏 / 绑定显示器菜单）；M2.2 通用渲染 = 组件固定 series 逐个渲染「数值卡 + 曲线」；
- **专用渲染（M2.3 / M2.4）**：`sys-dashboard`（「资源仪表盘」）注册专用渲染器 `SysDashboard.svelte`——**汽车仪表盘式布局**：上方左右两个大仪表（CPU / 内存占用率）、下方左右两个小仪表（磁盘活动率 / 网络利用率）；表盘为 **SVG 240° 弧形**（以 12 点位为 0°、顺时针为正、行程 -120° → +120°——即真实汽车仪表盘几何：0 在 8 点方向、50 在 12 点顶部、100 在 4 点方向），含外圈金属边框、长短刻度、0/25/50/75/100 数值标签、红区（阈值→100）、指针 + 尾翼、中心 hub、**组件名印于表盘内**（hub 下方，弧底部开口处空白；紧凑模式借此省掉独立标签行的高度）；霓虹辉光（表盘径向渐变面板 + 指针/红区 drop-shadow）。每个仪表下方一个**指示灯**：指标占用率超其适配器 `high_threshold`（默认 80，pano.toml 每适配器可配）→ 亮红，否则绿色；数据取自窗口数据管道 `latest`，阈值经 `list_adapters` 的 `config` 读取；**磁盘仪表显示当前最忙盘符与活动率**（盘符取自 `sys.disk.busiest_disk`，数值取自 `sys.disk.active_percent`）；
- **小分辨率自适应（M2.4 动态适配）**：`SysDashboard` 用 `ResizeObserver` 观察容器（`ComponentWindow` 的 `main` 设 `min-height:0` 使其收缩到可视高度——flex 子项默认 `min-height:auto` 会把容器撑开，导致小屏紧凑布局永不触发，此为 400×100 仍显示 2×2 的根因修复），**布局完全随可用空间推导、无硬编码尺寸**：高度 ≥120px → 常规 2×2，大/小表盘（比例 1:0.73）按宽高双约束缩放（上限 300 保大屏观感）；高度 <120px → 紧凑：按宽高比定列数（宽横屏 4 列一排 / 近方 2×2），表盘尺寸 = `min(每列宽, (容器高-开销)/0.66)`；极端矮（<50px）→ 隐藏读数行（只留表盘，组件名已印于表盘内）；标签换短名、磁盘最忙盘符拼入标签——支持 **400×100 小屏（含 125% 缩放：物理 400×100 → 逻辑 320×80，main 内高约 58，紧凑表盘 ~50 不裁切）**；`Gauge` 提供**紧凑样式**（`compact` prop：padding/读数行/间距/指示灯缩减，垂直开销 ~32→25 含边框）与 **`readout` 开关**（隐藏读数行省高度）；`ComponentWindow` 窗口壳监听窗口尺寸（`innerSize` + `onResized`，**物理像素按 scaleFactor 换算为逻辑像素**后与阈值比较——高 DPI 下单位不一致会导致紧凑判定错位），窗口高度 < 140px 时折叠头部控件（仅留组件名单行极简条）并压缩内容区 padding，把高度让给仪表；两层阈值配合保证 h<100 场景必命中紧凑布局；
- **无边框 + 内容拖拽（M2.4）**：`sys-dashboard` 组件默认声明无边框（`WindowSpec.decorations = false`，小屏开箱即用）；组件在可拖区域声明 `data-pano-drag`（`SysDashboard` 整块仪表盘、窗口壳 header 组件名），**窗口壳**（ComponentWindow，持 `getCurrentWindow`）在无边框时于 mousedown 委托 `startDragging` 移动窗口——组件只声明标记、平台调用收敛在壳（换窗口后端组件零改动）；有边框窗口由系统标题栏拖动；无边框切换经「窗口管理」页开关（命令层 → 窗口服务 → 定向 emit `pano://window-decorations` 事件同步前端）；
- **小屏初始尺寸收敛（M2.4 修复）**：建窗时若声明尺寸超出目标显示器可用工作区（无持久化记忆尺寸时），按工作区收敛（`fit_size_to_work_area`）——400×100 小屏上 860×540 的默认窗口不再溢出屏幕；用户手动调整过的尺寸（布局记忆）不被覆盖；
- **DeepSeek 额度组件（M2.5）**：`deepseek-balance`（「DeepSeek 额度」）专用渲染器 `DeepSeekBalance.svelte`，数据源 = 远程适配器 `deepseek.balance`（DeepSeek API 余额，架构 §7 / roadmap M2.5）。布局自上而下：**状态条**（`is_available` 徽标 + **高峰时段徽标**（周一~周五 9:00~12:00 / 14:00~18:00 = 高峰**价格翻倍**，本地时间判定；其余空闲）+ **低余额指示灯**（`total_cny < low_threshold`（缺省 20，经 `list_adapters` config 读取，仿 `high_threshold` 路径）亮红）+ 适配器 Error 提示（last_error））；**CNY 主卡**（大数字 `¥total_cny`（低阈值变红）+ 充值/赠送细分 + **近 5 分钟 / 近 30 分钟消耗**行（由 `total_cny` 样本差分计算，数据不足显「—」，期间充值记 0））；**USD 副卡**（`total_usd` series 存在才显示）；**uPlot 趋势曲线**（`total_cny` 最近 300 点）。空态：无数据不显示 0 误导；安全：`api_key` 经 `list_adapters` 读回掩码（不进 WebView）；默认窗口有边框（520×420），可按需在窗口管理页切换无边框（内容区 `data-pano-drag` 拖拽）。
- **窗口标题**：播种 / 新建窗口默认取组件默认标题（`ComponentSpec.window.title`），可经 `create_window` 的 `title` 参数覆盖；标题为窗口独立属性（持久化于 `[window.<id>].title`），切换组件不改变标题；
- 空态：组件绑定**已注册但未启用**的适配器时，窗口显示空态（无「0」误导）；组件对应适配器**未注册**（feature 未编译）时组件在「窗口管理」页置灰不可选、不会建窗；
- **重启恢复**：持久化窗口绑定的组件在新构建中未注册（feature 关闭）时跳过建窗并 warn 日志（取向与首次播种「无数据源不建窗」一致），其余窗口正常恢复；
- 组件声明 `WindowSpec`：窗口标题、初始尺寸 / 位置、允许置顶 / 全屏 / 显示器绑定；
- 窗口控制按钮 → `WindowHandle` API（经 Tauri 命令转发到 Rust 窗口服务）；
- 托盘「窗口列表」列出全部窗口（管理 + 监控，随运行时注册表动态重建），点击打开 / 聚焦。

## 5. 组件与视觉规范

- 字体：系统默认 + 中文回退（M1 已验证中文渲染）；
- 暗色默认色板：
  - 背景 `#1e1e1e`、面板 `#252526`、边框 `#333`；
  - 强调色 `#4f9cf9`（蓝）；
  - 状态色：成功 `#3fb950` / 警告 `#d29922` / 错误 `#f85149`；
  - 曲线色板：蓝 / 青 / 绿 / 橙 / 紫，依序取用；
- 间距 8px 基准；面板圆角 4px；状态徽标 = 圆点 + 文字；
- 前端以 CSS 变量实现主题（暗色默认，亮色切换预留）。
- **仪表盘视觉（M2.4 升级）**：汽车仪表盘面板 = 径向渐变底 + 内阴影 + 圆角（`.gauge`）；霓虹辉光经 `filter: drop-shadow` 施加于指针 / 红区 / 指示灯 / hub；红区与超阈值状态共用错误色 `--err`，正常指示灯 `--ok`，辉光同色系。

## 6. 渲染与刷新策略（M1.2：事件驱动）

- **数据驱动刷新 = 事件推送**：pano-ui 桥接层（Rust）订阅 `SampleStore`，任一 series 出现新样本 → Tauri 事件 `emit`（按窗口订阅分发）→ 前端 `listen` → 更新数值卡 / 曲线；
- **无轮询、无帧内检测**：Tauri 前端由事件驱动渲染，空闲不空转（egui 版「UI 唤醒线程轮询」方案不再需要，见 roadmap §M1.1 教训）；
- **窗口渲染互不阻塞**：每个窗口独立 WebView 渲染进程，管理窗口高频交互不影响组件窗口刷新（根治 M1.1「管理窗口移动鼠标 → 组件窗口数秒不刷新」）；
- 前端可配置刷新节流（如曲线 500ms 粒度重绘，高频事件合并）；
- 曲线只取最近 N 个样本（如 300 点）绘制，避免全量历史重算。

## 7. 交互细节

- 启停 / 重启有状态反馈：进行中禁用按钮，toast 显示结果；
- Error 状态：行内红色徽标 + 悬停 tooltip 显示最后错误；
- 空数据 / 未启用适配器的面板显示空态，而不是 0；
- 窗口控制：每个窗口「置顶」「全屏」「显示器」控制（API 调用，运行期切换）；
- 文案走常量表：M1 中文硬编码，M3 抽 key 预留 i18n。

## 8. 可替换性说明（UI 侧）

- `pano-ui` 是独立 crate：Rust 命令层 + 前端（`web/`），入口接收 `CoreHandle`（只读 API）+ `WindowService` + `UISpec` 声明；
- **组件与窗口分离是硬约束**：组件只持 `WindowHandle`，不依赖任何窗口实现细节——换窗口后端（如换掉 Tauri）组件零改动；
- 前端框架（Svelte 等，§10）是 pano-ui 内部实现：新 UI = 新 crate 实现同一接入协议（UISpec + 事件订阅 + WindowHandle），前端形态自由；
- 托盘集成属于 pano-app / pano-ui 装配层，不影响 core / adapters。

## 9. 技术要点（Tauri v2）

| 需求 | 实现 |
| --- | --- |
| 多独立窗口 | `tauri::WebviewWindow`，每窗口独立 WebView 渲染进程；管理窗口 + 组件窗口 |
| 置顶 / 全屏 | Tauri 窗口 API：`set_always_on_top` / `set_fullscreen`（Rust 侧命令暴露给前端） |
| 绑定显示器 | Tauri monitor API：枚举显示器 → `MonitorId` → `set_position` 定位 / 全屏到指定显示器 |
| 位置 / 大小记忆 | 布局持久化：`[window.<id>]` 配置段（位置 / 大小 / 显示器），启动恢复 |
| 无边框窗口 | 建窗 `decorations`（组件声明 + `[window.<id>].decorations` 覆盖合并）；运行期 `set_decorations` 即时切换；无边框时内容 `data-pano-drag` 区域经 `startDragging` 拖拽移动（M2.4） |
| 隐藏不退出 | 关闭请求 → 拦截（`CloseRequested`）→ 隐藏窗口；托盘「退出」才结束进程 |
| 托盘 | `tray-icon` crate（主进程侧）；菜单事件 → 命令 → 打开 / 聚焦窗口、退出 |
| 数据推送（core → 前端） | 桥接层订阅 SampleStore → `AppHandle.emit` 事件 → 前端 `listen` |
| 前端 → Rust | Tauri 命令（`invoke` + `tauri::command`）：窗口控制、适配器启停 / 配置 |

## 10. 前端技术栈（推荐方案，可替换）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **Svelte 5** | 轻量、编译期、反应式；多窗口（多 entry / 多路由）开销小，适合单机面板 |
| 构建 | **Vite** | Tauri 官方模板标配，开发热更新 |
| 图表 | **uPlot** | 时间序列极快（微秒级重绘），适合 500ms 采样的实时曲线；备选 ECharts（功能全、体积大） |
| 语言 | TypeScript | 与 Rust 侧命令类型对应（命令参数 / 返回值类型化） |
| 测试 | Vitest（前端单测）+ Playwright（可选端到端） | 替代 egui_kittest 的定位（spec §10） |

备选：React / Vue + ECharts（生态更大，包体与复杂度更高）。**前端栈是 pano-ui 内部实现，可在编码前替换，不影响其他层**。

> 决策待确认项：若对前端框架有偏好（如团队更熟 React / Vue），在 M1.2 编码前提出即可，仅影响 `pano-ui/web/` 内部。

## 11. 动态 UI 插件（M4）

动态 UI 插件 = 运行期可装载的组件类型（架构设计见 `architecture.md` §15；决策见 `roadmap.md` M4.2）：

- **目录与 manifest**：`ui-plugins/<plugin-id>/`（`manifest.json` + `dist/`）；manifest 声明 `id / name / version / min_pano_version / series / window / entry`（`series` / `window` 与 `ComponentSpec` 同构）；启动扫描后与编译期组件目录合并成运行期组件目录；
- **装载**：Tauri 自定义协议 `ui-plugin://<plugin-id>/<path>` 服务插件 `dist/`（路径规范化防穿越）；**每插件组件实例独立 WebviewWindow** 加载 `ui-plugin://<plugin-id>/<manifest.entry>`（缺省 `index.html`）；与 §2「1 窗口 = 1 组件、多窗口可绑定同一组件」一致，插件组件亦可多窗口绑定；
- **数据管道**：与编译期组件完全一致——`seriesList / samples / latest` 经事件桥推送（§6）；插件前端只需按与主壳相同的 IPC 契约订阅，不依赖主壳内部实现；
- **权限**：插件窗口 Tauri ACL 仅授予其声明 series 的事件订阅 + 建窗 / 窗口控制命令（`WindowSpec → core → 窗口服务`）；插件不接触窗口实现与适配器逻辑（铁律 / issue §4）；
- **建窗与切换**：与现有「窗口管理」（§3.2）一致——`list_components` 含插件组件、可绑定窗口、可切换组件（切换 = 换 `ui-plugin://` 装载）；卸载 = 删除插件目录，**下次启动扫描时消失**；
- **约定**：插件前端为「无框架绑定」的 Web 构建产物（Svelte / React / Vue 皆可，dist 自包含），仅依赖 Pano 注入的 IPC 契约与自定义协议入口。
